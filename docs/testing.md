# 验证说明（v0.2.0）

本文记录 v0.2.0 在作者环境中的验证情况。自动回归和人工试玩是两类不同的证据，下面分开说明。

## 验证环境

- 操作系统：Windows 11
- 浏览器：Chrome 157，无头模式，视口 1280×720（自动回归）
- 日期：2026-11-12 至 2026-11-13

## 验证范围

| 类别 | 内容 |
| --- | --- |
| 自动回归 | 45 项行为检查，由脚本向浏览器发送键盘事件并读取游戏状态 |
| 人工试玩 | 作者试玩一次 |
| 启动方式 | 在 Windows 11 上运行 `scripts\play.cmd` |

## 自动回归

45 项检查按内容分为：

| 分组 | 项数 | 内容 |
| --- | --- | --- |
| 基本操作 | 12 | 标题与开始、移动、同方向双键、跳跃高度、冲刺与冷却、挥击判定、暂停、失焦自动暂停、静音、调试显示 |
| 危险区与重置 | 4 | 荆棘扣血并回到安全落点、生命归零后倒下、未点燃烬灯台时回到入口、暂停菜单重新开始 |
| 房间与检查点 | 14 | 三个房间的进入与返回、到达后不重复触发、连续 8 次往返、冲刺和跳跃中过门、锈壳虫的伤害与击倒及重新出现、烬灯台点燃与再次休息、守卫在重新进入时恢复、倒下后在烬灯台旁醒来 |
| 完整通关 | 10 | 从标题界面打到通关界面，途中点燃烬灯台、击败守卫，并在拱门开启后往返一次确认状态保留 |
| 进度保留 | 2 | 倒下后进度保留、倒下并醒来后仍可通关 |
| 其他 | 3 | 未击败守卫时拱门不能通关、音频数值、全程控制台无错误 |

操作方式：

- 41 项只使用浏览器级键盘事件，游戏收到的事件与真人按键相同，脚本不改写游戏状态。
- 1 项（失焦自动暂停）使用合成的失焦事件。
- 1 项（未击败守卫时拱门不能通关）通过测试接口直接把角色放到拱门处。
- 另有音频数值检查和控制台监听各 1 项。

结果：

- 开发阶段（2026-11-12）：45 项全部通过，浏览器控制台无错误或警告。
- 发布文件（2026-11-13）：对本仓库中的 `game/index.html` 重新运行一轮，45 项全部通过，控制台无错误。发布文件与开发阶段被测的文件相比，只改动了一行代码注释。

自动检查脚本由 Claude Code 编写并执行。

## 启动方式

2026-11-13 在 Windows 11 上运行本仓库的 `scripts\play.cmd`：本地服务在 127.0.0.1 上启动，请求游戏页面返回 HTTP 200，内容与 `game/index.html` 一致。这次没有确认默认浏览器是否自动打开；v0.1.0 时确认过同一启动方式会在默认浏览器（Microsoft Edge）中打开页面。

## 验证限制

- **自动通关依赖内部状态。** 全部按键检查都通过游戏的调试接口读取坐标、敌人状态和房间数据来决定按键时机，不依据画面判断。它验证的是游戏逻辑可以走通，不反映玩家的实际操作体验和难度。
- **未经独立复核。** 自动检查由开发时使用的同一工具编写和执行，没有第三方复核。
- **人工试玩范围有限。** 反馈只有“试玩通过”，没有对手感、难度、房间长度、切换房间的观感作出评价。
- **音效未经试听确认。** 音效（包括 v0.2.0 新增的三个）只做过离线渲染的数值检查（无 NaN、无削波、非静音）。
- **性能未测。** 没有测量帧率和内存占用。
- **跨浏览器验证未完成。** 自动回归只在无头模式的 Chrome 中进行；有界面的 Chrome、Edge、Firefox 等没有做行为检查。
- **重复次数有限。** 完整的 45 项只在开发阶段和发布文件上各跑过一轮，没有多轮重复来估计偶发失败的概率。
- **没有专门检查的情况。** 切换房间的淡出过程中按暂停、守卫把玩家击退进出口、经高处平台越过烬灯庭的荆棘坑。
- **其他未测项。** 直接以文件方式打开 `game/index.html` 未测试；切换窗口时的自动暂停只用合成事件验证过。
